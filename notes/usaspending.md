## 1. What the source is

USAspending.gov (U.S. Treasury, Bureau of the Fiscal Service) republishes every US federal **prime contract transaction** reported to FPDS (Federal Procurement Data System) and every **subaward report** prime contractors file in SAM.gov (formerly FSRS) under FFATA. The "Custom Award Data Download" API (`POST https://api.usaspending.gov/api/v2/bulk_download/awards/`) generates a zip with one CSV of prime transactions (`All_Contracts_PrimeTransactions_*.csv`, 297 columns) and one of subaward reports (`All_Contracts_Subawards_*.csv`, 118 columns), filtered server-side by recipient location.

Landing page used as `source.dataset_url`: https://www.usaspending.gov/download_center/custom_award_data  
API docs read: https://api.usaspending.gov/docs/endpoints ; endpoint contract https://raw.githubusercontent.com/fedspendingtransparency/usaspending-api/master/usaspending_api/api_contracts/contracts/v2/bulk_download/awards.md and `.../download/status.md`; backend validator/filter code (`download/v2/request_validations.py`, `common/query_with_filters.py`, `download/v2/download_column_historical_lookups.py`, `download/filestreaming/download_generation.py`, `search/filters/time_period/*`) saved under `downloads/usaspending/docs/`.  
Data dictionary: https://files.usaspending.gov/docs/Data_Dictionary_Crosswalk.xlsx (110,540 bytes, retrieved 2026-10-25 12:21 UTC; sheet "Public"; the definitions of the columns used are extracted to `docs/crosswalk_selected_fields.txt`).

## 2. Retrieval

### 2.1 Exact request body
The endpoint caps `date_range` at 366 days (`InvalidParameterException: date_range total days must be within a year`, `request_validations.py` line 270) and requires a non-empty `agencies` list (an empty list is rejected with HTTP 422 `Field 'filters|agencies' value '[]' is below min '1' items`; the frontend's "all agencies" sentinel `{"type":"awarding","tier":"toptier","name":"all"}` is accepted and stripped server-side, confirmed by `download_request.filters.agencies == []` in every response). So **27 requests were submitted, one per federal fiscal year FY2001..FY2027**, all identical except `date_range`:

```json
{
  "filters": {
    "prime_award_types": ["A", "B", "C", "D", "IDV_A", "IDV_B", "IDV_B_A", "IDV_B_B", "IDV_B_C", "IDV_C", "IDV_D", "IDV_E"],
    "sub_award_types": ["procurement"],
    "date_type": "action_date",
    "date_range": {"start_date": "2025-10-01", "end_date": "2026-09-30"},
    "recipient_locations": [{"country": "CAN"}],
    "agencies": [{"type": "awarding", "tier": "toptier", "name": "all"}]
  },
  "file_format": "csv"
}
```
`date_range` per FY = `YYYY-1-10-01` .. `YYYY-09-30`; FY2027 = `2026-10-01` .. `2026-10-25` (reference date). Overall coverage therefore = **action_date 2000-10-01 .. 2026-10-25**, the full range the API holds (`API_MIN_DATE = 2000-10-01` in `settings.py`).

Server-side filter semantics (from backend source): for the prime file the filter is applied to the **transaction_search** table (`VALUE_MAPPINGS["prime_awards"] = VALUE_MAPPINGS["transactions"]`), i.e. rows are *transactions* with `action_date` in range and `recipient_location_country_code == 'CAN'` (`geocode_filter_locations("recipient_location", ...)`). For the subaward file the filter is applied to **subaward_search** in Elasticsearch with `sub_recipient_location_country_code == 'CAN'` and `sub_action_date` in range (`_RecipientLocations` uses the `sub_` prefix for `QueryType.SUBAWARDS`; `SubawardSearchTimePeriod` maps `action_date` to `sub_action_date`). So the subaward file is filtered on the **sub-recipient's** location, which is exactly what we need. Every downloaded prime row has `recipient_country_code == 'CAN'` (183,009 / 183,009) and every subaward row has `subawardee_country_code == 'CAN'` (2,224 / 2,224).

Status polling: `GET https://api.usaspending.gov/api/v2/download/status?file_name=<file_name>` every 20–30 s until `status == "finished"`, then `curl -sS -L -C - --retry 5` of `file_url` (`https://files.usaspending.gov/generated_downloads/<file_name>`), unzip into `extracted/FY<year>/`. Jobs took 78–160 s each. Submission timestamps 2026-10-25 12:17:32 UTC (FY2026) and 12:20:15–12:21:40 UTC (others); downloads completed 12:18:54–12:31:41 UTC. `source.retrieved_at` on each record = the download completion time of the FY file that contributed the record's latest row.

Two transient proxy/WAF `HTTP 500 "Web Page Blocked!"` responses on submit were retried successfully after 10 s. One background poll process was killed mid-run and re-launched with `setsid`; no data loss (state per FY is persisted in `requests/FY*.json`).

## 3. From rows to records

### 3.1 Prime awards
The prime CSV is **transaction-level** (one row per FPDS action: base award + every modification). 183,009 rows describe **138,462 distinct awards** (`contract_award_unique_key` = `generated_unique_award_id`, format `CONT_AWD_<PIID>_<agency>_<parentPIID>_<parentAgency>` or `CONT_IDV_<PIID>_<agency>`). 12,266 awards have rows in several FY files (max 19 FY files for one award). Rows were merged per award across all 27 files:

- **Latest transaction** = max of (`action_date`, `last_modified_date`, `modification_number`). Its values feed the normalized layer (dates, values, vendor, buyer, commodity); all rows of the award go verbatim into `raw.rows` (sorted oldest→newest; `raw.row_source_files` says which CSV each came from), and the latest row's 297 columns are also spread at the top level of `raw`.
- The `period_of_performance_*`, `ordering_period_end_date`, `current_total_value_of_award`, `potential_total_value_of_award`, `total_dollars_obligated`, `*_for_overall_award` columns are award-level cumulative values restated on every transaction (crosswalk: "Current Completion Date … revised scheduled completion date" after modifications), so the latest row carries the current state.

**Canadian vendor** = `recipient_country_code == "CAN"` (FPDS `LegalEntityCountryCode`, ISO 3166-1 alpha-3 GENC) on the latest transaction. The server filter already guaranteed this for every row; it is re-checked in `normalize.py` (`vendor.country_basis` on every record names the field).

**Status rules (primes)** — evaluated on the latest transaction:
- start = `period_of_performance_start_date` (blank for 1 of 138,462 awards → fall back to earliest `action_date`, documented in `status_basis`).
- end = `period_of_performance_current_end_date` for awards (`award_or_idv_flag == "AWARD"`: types A/B/C/D); for IDVs (`award_or_idv_flag == "IDV"`) the FPDS "Current Completion Date" is always blank in this data (2,412 / 2,412 IDVs), so end = **`ordering_period_end_date`** ("Indefinite Delivery Vehicle Last Date to Order", the date after which no new orders may be placed; orders already issued may run beyond it). This is what USAspending's own award page/API shows as the IDV `period_of_performance.end_date` (verified: `CONT_IDV_W911SR20D0002_9700` API end_date 2027-08-26 == our ordering_period_end_date).
- `ongoing` ⇔ end ≥ 2026-10-25 and start ≤ 2026-10-25.
- `end_date_unknown` ⇔ end blank and start ≤ 2026-10-25 (7 records, all FY2001–FY2008 legacy records: 3 Inscape Corporation GSA-schedule delivery orders and 4 IDVs with no ordering-period end).
- Excluded: end < 2026-10-25 (134,547 awards + 2,072 IDVs); start > 2026-10-25 (6 not-yet-started awards); and 21 awards whose dates look ongoing but whose **latest transaction is a cancellation/close-out**: `action_type_code` N "LEGAL CONTRACT CANCELLATION" (17), K "CLOSE OUT" (1), F "TERMINATE FOR CONVENIENCE (COMPLETE OR PARTIAL)" with `current_total_value_of_award` ≤ 0 (3, i.e. complete terminations). 7 awards whose latest action is type F but which still have a positive current value are kept as `ongoing` with a note in `status_basis` (partial termination).
- 48 ongoing records have end dates ≥ 2050 (`9999-09-09` ×18, `2060-12-25` ×28, `2107`, `3006`), all legacy DoD/CCC records last modified 2001–2011. They satisfy the published-end-date ≥ today rule and are kept, but `status_basis` carries an explicit "looks like a legacy placeholder" caution. More generally, 55 of the 1,816 prime records had their last FPDS action before 2015; their "ongoing" status rests solely on an end date that was never updated/closed out in FPDS.

**Result: 1,816 prime records = 1,809 `ongoing` + 7 `end_date_unknown`.**

Normalized-field mapping (prime):
- `record_id` = `usaspending:<contract_award_unique_key>`; `source.record_url` = the row's `usaspending_permalink` column (`https://www.usaspending.gov/award/<contract_award_unique_key>/`). Verified: `https://www.usaspending.gov/award/CONT_AWD_16PBGC24P0012_1665_-NONE-_-NONE-/` → HTTP 200, and the same key resolves at `https://api.usaspending.gov/api/v2/awards/CONT_AWD_16PBGC24P0012_1665_-NONE-_-NONE-/` with matching PIID, recipient (CEM Benchmarking Inc, Toronto, UEI W8CVD8EEA6A3) and dates. A random sample of 10 ongoing records was re-checked against the live awards API: start/end dates and recipient country matched in 10/10.
- `contract.instrument_type` from `award_type_code` (A → "BPA call", B → "purchase order", C → "delivery order", D → "definitive contract") or, for IDVs, `idv_type_code` (A GWAC / B IDC / C FSS / D BOA / E BPA) plus `type_of_idc` (IDIQ / requirements / definite quantity) and `multiple_or_single_award_idv`, e.g. "IDV (IDC: INDEFINITE DELIVERY / INDEFINITE QUANTITY), single award".
- `contract.identifiers`: `contract_award_unique_key`, `piid`, awarding agency/sub-agency codes, `parent_award_id_piid` + `parent_award_agency_id` (referenced IDV), `solicitation_identifier`, latest `contract_transaction_unique_key` + `modification_number`, and the lists of all transaction keys / mod numbers.
- `contract.value` = `current_total_value_of_award` (FPDS "Total Base and Exercised Options Value"; for IDVs this column is blank so `potential_total_value_of_award` = ceiling "Total Base and All Options Value" is used instead; 332 records). `value_detail` keeps current, potential, `total_dollars_obligated`, outlays, the latest mod's base/exercised and base/all-options values, the latest mod's `federal_action_obligation` and the sum of `federal_action_obligation` over the rows we hold. Currency USD. NB: IDV ceilings can be huge (two $151 bn DISA IDIQs), so do not sum `value` across records naively; `total_dollars_obligated` is the actual spend.
- `contract.dates`: `published` = earliest `initial_report_date` (date FPDS first reported the award), `signed` = earliest `action_date` (base award), `start`/`end` as above, `amended_last` = latest `action_date`, plus `potential_end`, `ordering_period_end`, `last_modified`, `solicitation_date`.
- `contract.commodity`: `naics` + `naics_description`, `psc` (`product_or_service_code`) + `psc_description`. `procurement_method` = `extent_competed`, `solicitation_procedure` = `solicitation_procedures`; set-aside and pricing type also kept.
- `contract.related`: parent IDV id/agency/unique key/URL (`CONT_IDV_<parentPIID>_<parentAgency>`, pattern verified against the API `parent_award.generated_unique_award_id`), API URL, funding agency/sub-agency/office names+codes, place of performance, latest action type, transaction count.
- `buyer` = awarding agency (`awarding_agency_name`, code) with `sub_agency_name`/`office_name` and their codes; `buyer.country` = "US"; `buyer.type` = "US federal department/agency".
- `vendor`: `recipient_name` (+ `name_raw`, DBA), identifiers `uei`, `duns`, `cage`, `parent_uei`, `parent_duns`, `parent_name`; address `recipient_address_line_1/2`, `recipient_city_name`, region = `recipient_state_name` (FPDS puts the Canadian province code here, e.g. ON/QC/BC; `recipient_state_code` is always blank for foreign addresses), `recipient_zip_4_code` (Canadian postal code), country `CAN`; contact phone/fax.

### 3.2 Subawards (subcontracts to Canadian sub-recipients)
The subaward CSV is **report-level**: one row per monthly SAM.gov subaward report (`subaward_sam_report_id`, unique). Reports carry no end date or period of performance of their own, only `subaward_action_date` and `subaward_amount`, plus the prime award's dates. 2,224 report rows (FY2015–FY2027; FFATA subcontract reporting in this data effectively starts 2021) were grouped into **1,979 subcontracts** keyed on (`prime_award_unique_key`, `subaward_number`, `subawardee_uei`) — the crosswalk warns that `subaward_number` alone is not unique, and a single (prime, subaward_number) pair with two different UEIs exists in the data. All reports of a group go into `raw.rows`; the newest report's 118 columns are spread in `raw`.

- `record_id` = `usaspending:sub:<prime_award_unique_key>:<subaward_number>:<subawardee_uei>` (there is no stable public subaward key in the file; `subaward_sam_report_ids` are listed in `contract.identifiers`). `source.record_url` = the row's `usaspending_permalink`, which is the **prime award's** page (USAspending has no subaward page; verified `https://www.usaspending.gov/award/CONT_AWD_0001_9700_FA870215D0001_9700/` → HTTP 200). Note the subaward permalink column therefore does not identify the subaward itself.
- `instrument_type` = "subcontract"; `buyer` = the prime contractor (`prime_awardee_name`, UEI/DUNS/parent, address, country) with `buyer.type` "company (prime contractor to the US federal government)"; the awarding/funding agency names+codes and prime PIID/parent PIID are in `contract.related` / `contract.identifiers`.
- `vendor` = sub-awardee (`subawardee_name`, UEI, DUNS, parent, address line/city/province code/foreign postal code, country CAN); `country_basis` = `subawardee_country_code == 'CAN'`.
- `value` = sum of `subaward_amount` over the group's reports (reports are incremental actions, including negative de-obligations); the latest report's amount and the per-report list are in `value_detail`. `dates.signed` = earliest `subaward_action_date`, `amended_last` = latest, `published` = earliest `subaward_sam_report_last_modified_date`. Commodity = the prime award's NAICS (flagged as such).
- **Status**: `ongoing_inferred` when the prime award's current end date ≥ 2026-10-25 and `subaward_action_date` ≤ 2026-10-25. The prime end date comes from the subaward file column `prime_award_period_of_performance_current_end_date` (851 records); when that is blank (always the case for prime IDVs — 108 rows / 61 primes) it was taken from the prime IDV's `ordering_period_end_date` in our own prime download (26 records) or, failing that, from the live awards API `period_of_performance.end_date` (22 records; 22 API calls, 0 failures; API response stored in `raw.prime_award_api_response`). `status_basis` names the source used on every record. Excluded: 1,080 subcontract groups whose prime award ended before 2026-10-25. No `end_date_unknown` subcontracts remained.

**Result: 899 subcontract records, all `ongoing_inferred`** (767 under US-located primes, 132 under Canadian-located primes — those 132 primes are themselves prime records in this file).

## 6. Known gaps and limits

- **Location, not ownership.** Vendor = entity whose SAM-registered legal business address is in Canada (`recipient_country_code == CAN`). Canadian-owned firms contracting through a US subsidiary/US address (e.g. CAE USA, Bombardier's US entities, Magna US plants) are excluded by design; conversely, Canadian subsidiaries of foreign groups (Safran Canada, GDLS-Canada, Honeywell Aerospace International, Pratt & Whitney Canada) are included. Many Canadian suppliers to DoD appear only under **Canadian Commercial Corporation** (477 prime records), the Canadian Crown corporation that signs as prime; the actual Canadian manufacturer is often not named in FPDS (sometimes visible in the description or as a CCC subcontract report).
- **Status for primes rests on FPDS dates.** `period_of_performance_current_end_date` is only as current as the last modification reported; agencies do not always file close-out mods, so some records with old last actions (55 with last action before 2015; 48 with placeholder-like end dates 2060/9999) are probably administratively dead. They meet the written rule and are kept, with cautions in `status_basis`. Awards whose latest action is a cancellation (N), close-out (K) or complete termination (F with value ≤ 0) were excluded even though their dates looked ongoing (21 awards).
- **IDVs** use the ordering-period end as "end"; an IDV whose ordering period has closed but whose orders still run is excluded as an IDV, while its orders (separate `CONT_AWD_` records) are evaluated on their own dates. IDV `value` is the ceiling, not spend.
- **Subcontracts** have no end date of their own in FFATA/SAM.gov; `ongoing_inferred` means only that the prime is still within its period of performance. Subcontract reporting is mandatory only above the FFATA threshold ($30k) and is known to be incomplete; the 2,224 reports are a lower bound. No subaward-level public URL exists; `record_url` points at the prime award. The grouping key (prime, subaward_number, sub UEI) is a reasonable but not guaranteed identity for a subcontract.
- **Transactions, not award summaries.** The bulk endpoint returns FY-filtered *transactions*; an award is in scope if any of its transactions (base or mod) has an action_date 2000-10-01..2026-10-25 — i.e. every award in the database, since this is the API's full range. `raw.rows` holds every transaction of the award that the API returned; `dates.signed` is the earliest action we hold.
- Amounts are FPDS cumulative values in USD; `federal_action_obligation_sum_of_rows` is a convenience sum and may differ from `total_dollars_obligated` where FPDS has transactions we did not receive.
- Addresses: Canadian province is in `recipient_state_name` (two-letter code, occasionally "PQ", "NF" or spelled out "ONTARIO"); `recipient_zip_4_code` holds the Canadian postal code; 25 prime records (mostly CCC/GDLS-Canada legacy rows) lack province and postal code.
- Data as of the USAspending nightly load available on 2026-10-25; FPDS has a 90-day reporting lag for DoD, so the latest DoD actions (and some FY2027 awards) may not yet be present.
